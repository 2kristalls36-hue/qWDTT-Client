# Поколения сессий на сервере

Статус: изменение предложено в основной репозиторий qWDTT (SpaceNeuroX/proxy-turn-vk-android), ветка `raw-session-generations`. В версии 1.2.0 выполняется только клиентская часть плана стабильности подключения.

## Проблема

После смены сети (Wi‑Fi ↔ мобильная сеть) все потоки клиента теряют связь со своими relay VK, однако сервер об этом не узнаёт:

- сервер хранит список потоков устройства и распределяет входящий трафик по кругу между всеми потоками, включая неработающие;
- неработающий поток удаляется только по таймауту простоя `idleTimeout` — 90 с, фактически 90–110 с из-за 20-секундного шага чтения;
- пакет `DISCONNECT_RAW` в этом случае не доставляется: он отправляется через старый поток, который уже недоступен.

Следствие: в течение 1,5–2 минут после смены сети часть входящего трафика теряется, скорость снижается. По замерам проекта anton48/vk-turn-proxy-ios (`pkg/proxy/pathrestart.go`) на аналогичной схеме скорость держится около 0,7 Мбит/с до удаления неработающих сессий сервером.

Проверено по коду сервера qWDTT 1.4.5 (SpaceNeuroX/proxy-turn-vk-android): `server/raw.go`, функции `rawRouter.register`, `rawRouter.pickDownlinkConn`, `handleConnRaw`. Механизма замены старых потоков новыми в сервере нет.

Устранить проблему только на стороне клиента нельзя: выбор потока для входящего трафика выполняет сервер, а запись в неработающий relay проходит без ошибок. Подключение под новым идентификатором устройства невозможно из-за привязки пароля к устройству.

## Предлагаемое решение (сервер)

- Клиент передаёт номер поколения именованным полем в `AUTH` и `GETCONF_RAW`: `AUTH:<deviceID>|<password>|gen=<мс>`. Номер поколения — время начала текущего подключения в миллисекундах; он увеличивается при каждой смене сети и не требует хранения. Поле именованное, а не позиционное: в сервере WDTT-панели (ildarmaga/wdtt) третье поле `GETCONF_RAW` занято под MTU.
- Сервер хранит номер поколения у каждого потока. При регистрации потока с бо́льшим номером сервер сразу отключает потоки того же устройства с меньшим номером.
- Обратная совместимость в обе стороны: серверы без доработки (qWDTT, WDTT-панель) поле не распознают и обслуживают клиента как раньше; клиенты без поля обслуживаются как раньше. Поэтому клиенту не требуется определять версию сервера: поле передаётся всегда.
- Признак поддержки: сервер сообщает `"features": ["raw_gen"]` в ответе `/api/profile/status`, который приложение уже запрашивает для сведений о подписке. Признак нужен только для отображения или для выбора поведения клиента в будущих доработках; старые клиенты лишнее поле не читают. Сообщать признак в ответе `RAWCONF` нельзя: клиенты ожидают в нём ровно три поля.
- Объём: около 100 строк в `server/raw.go` и `server/profile_api.go` вместе с комментариями; на клиенте — `go_client/protocol.go` и `go_client/session.go`; тесты — `server/raw_gen_test.go`, `go_client/protocol_gen_test.go`.

## Варианты доставки на сервер

1. Pull request в основной репозиторий qWDTT (SpaceNeuroX/proxy-turn-vk-android). Изменение попадает на сервер с очередным обновлением; собственную версию сервера поддерживать не требуется. Сроки зависят от владельцев репозитория.
2. Собственный форк сервера. Изменение доступно сразу, но обновления qWDTT переносятся в форк вручную, а деплой перенастраивается на собственную сборку.

## Частичная альтернатива без сервера

Порядок «сначала новое, потом прощание со старым»: при смене сети клиент поднимает новые потоки, пока прежняя сеть ещё доступна, затем отправляет `DISCONNECT_RAW` через старые потоки, и сервер удаляет их сразу.

Ограничения:

- работает только при плавной смене сети, когда прежняя сеть остаётся доступной некоторое время (по имеющимся сведениям, Android удерживает прежнюю сеть около 30 с после переключения; требуется проверка на устройстве);
- не помогает при резкой потере сети (выход из зоны Wi‑Fi, лифт);
- требует привязки сокетов каждого потока к конкретной сети Android, что затрагивает связку Go‑клиента и приложения и может вести себя по-разному на разных прошивках.
